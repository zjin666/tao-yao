# 桃夭 QQ 机器人（自写轻量版）

## 从 GitHub 下载后

先将 `config.example.json` 复制为 `config.json`，再设置自己的 QQ 号、群号和 API 密钥文件。
仓库不包含 `private/` 下的密钥、聊天数据、画像数据库、日志和备份；这些文件只保存在本机。
`models/` 和 `bin/` 为本机下载的模型与工具，也不随源码上传；使用相关功能前需要另行准备。

2026-11-04 表达更新：六维通过直接程度、关心显露、玩笑密度、帮助主动性、理由密度和互动节奏调整语气，不再规定每维的起句动作或多套百分比。语气提示只注入一次；关系和隐私规则保留。日常接话增加“继续互动、减少修饰性复述”的说明和正反示例，保留桃夭的改口与奇妙联想。

## 桃夭发出的聊天记录

独立保存在 `data/taoyao_chat_history/private.json` 和 `group.json`，与画像数据库分开。
私聊以对方用户 ID 为 JSON key，群聊以群号为 key，value 是桃夭已成功发送的消息数组。
每条含 `sent_at`（北京时间含时区）、`timestamp`、`time_source`、`message_id`、`content` 和原始 OneBot `message`。
同时保存 `timezone: Asia/Shanghai` 和 `sent_at_utc`（UTC 完整日期时间），可按用户所在地换算；记录时区不代表用户所在地。
优先使用接口返回的发送时间；未返回时使用发送请求的本机时间，标记 `local_send`。
逐条保存分段回复、图片、命令回复和主动问候；失败或超时不登记为发送成功。
不重复保存用户输入。旧画像记录不自动迁入，因为其中的模型回复未必与实际发送的分条内容一致。
这份独立档案不会随 `/reset` 或画像删除自动清除。

当前部署位置：`D:\tao-yao`。完全独立于 `dafeiyu`，不依赖 AstrBot。

不依赖 AstrBot 的轻量机器人：

- OneBot 11 反向 WebSocket，接 SnowLuma / NapCat
- DeepSeek 对话，桃夭人设
- SQLite 聊天记录 + 每 20 轮自动总结长期记忆
- 78 张桃夭表情，优先按桃夭刚生成的回复匹配 36 个情绪分类（含 `sorry` 抱歉、`gentle` 温柔）；每次取 Top-3，前两名接近时用相似组最高分 + 模型标签二次比较，匹配不到就不发
- 每个用户首次说话自动建画像：昵称、QQ、基础信息、性格、6 维分数、私聊/群聊记录
- 私聊能带自己的群聊记录；群聊默认不带任何私聊内容
- 长回复分条发送（桃夭可用 `||` 自己决定，系统也会按长度兜底）、owner/user 双角色、群聊 @ 触发
- 普通好友/群友走单独过滤、单独短期上下文，不继承哥哥的长期记忆
- `--mock` 模式不需要 key、不需要 QQ，就能测试整条消息链路

## 身份和过滤（owner / user）

- `owner_qq` 是你的大号，只有这个号是「哥哥」：可以用 `/reset`、`/记住`、`/状态`，会写长期记忆，人设语气最亲近。
- 其他好友是普通 `user`：可以聊天，但走单独会话、只保留最近几轮、不继承哥哥的长期记忆/事实；回复更短、更客气，不叫哥哥、不撒娇。
- 群聊里只有 `owner_qq` 是哥哥，其他人都是群友；群友必须 @ 才回，群上下文单独存，也不写长期记忆。
- 桃夭的小号**进群后**会自动把该群加入 `allowed_groups`，并私聊通知你；退群/被踢会自动移除。不会预先放行没加入的群。
- 普通用户消息会先过一层过滤：改人设、忽略规则、套系统提示、冒充哥哥/主人、要密钥/隐私，直接回「这个我不能接。」，不送进模型。
- 普通用户还有频率限制：默认 2 秒 1 条、每分钟 12 条；owner 不受限制。

相关配置在 `config.json` 的 `roles`：

```json
"roles": {
  "allow_user_private": true,
  "allow_all_groups": false,
  "auto_whitelist_joined_groups": true,
  "owner_group_require_at": false,
  "user_context_messages": 6,
  "group_context_messages": 10,
  "user_max_chars": 500,
  "user_rate_seconds": 2,
  "user_rate_per_minute": 12,
  "user_meme_probability": 0.2
}
```

- 好友私聊默认允许；不想让陌生人私聊就设 `allow_user_private: false`。
- 群默认白名单，但桃夭进群会自动加入；也可以手动把群号填进 `allowed_groups`。
- 想放开所有群就设 `allow_all_groups: true`（不建议，陌生人 @ 会花你的余额）。
- 普通用户的表情概率默认 0.2，比哥哥的 0.35 低。

## 长回复分条

- 桃夭正常写完整句子，用 `。`、`！`、`？`、`……` 结尾；系统一看到一句完整的话，就单独发一条 QQ 消息。
- 不需要用户提醒，也不需要她加 `||` 或任何分隔符；`||` 即使误写也会被删掉，聊天里不会出现。
- 短回复只发一条；长回复自动拆，owner 最多 4 条，普通好友最多 2 条。
- 发送前，句号 `。` 和分号 `；` 会从该条末尾删掉（命令回复也一样）；感叹号 `！`、问号 `？`、省略号 `……` 保留。
- 单句超过 70 字时，才在逗号处继续拆。
- 相关配置：

```json
"reply": {
  "segment": true,
  "max_chars": 70,
  "max_segments": 4,
  "min_delay": 0.25,
  "max_delay": 0.8
}
```

普通好友的条数在 `roles.user_max_segments`，默认 2。

## 用户画像

每个 QQ 第一次和桃夭说话时自动建一份画像：

- 昵称、QQ/ID、身份标签 `owner` / `user`
- 身份只由 QQ 是否等于 `setup-owner.cmd` 写入的 `owner_qq` 决定；昵称、群名片、自称都不算
- 基础信息：用户明确说过的年龄、性别、名字、爱好、不喜欢的东西
- 基础信息更新：没出现过的字段加入；重复或冲突的以**后一次**为准（例如先说喜欢猫、后说不喜欢猫，会从爱好移到不喜欢）
- 性格：由 6 维分数生成的中文描述
- 6 维分数：`AGG / INT / HUM / DEP / RAT / ACT`，初始 50；新用户**第一条消息**直接加本次完整向量，之后才用 EMA 0.3 平滑
- 每条消息的 6 维判断（bucket、候选、confidence、delta、前后值）存在 `profile_updates` 表，`/画像` 显示最近一次
- 六维会生成「对话提示」放进 system prompt；按七档区间和组合规则调整语气，不直接改写桃夭人格
- 用户历史每新增 **50 条消息**后台压缩一次画像摘要（500 字内），摘要后热表保留最近 **35 条**原文，旧的移入 `user_messages_archive`
- 私聊能看到自己的私聊 + 所有群聊记录；群聊默认只看到当前群记录
- 群聊里发 `/公开私聊`，下一条才会把自己的私聊 + 当前群内容带进上下文（一次性），不会带其它群
- 群聊 system prompt 不注入私聊基础信息、私聊摘要和私聊性格描述，避免从画像侧漏私聊
- 只有 owner 能在私聊里用 `/画像 <QQ>` 查别人；普通用户只能看自己

6 维打分逻辑来自 `D:\Classifier_User_Attributes\Model.py`：固定语义桶增量 + 置信度衰减 + EMA 平滑。

分类器是 **规则 + 中文语义模型** 的 hybrid：

- 明确信号（「找打」「帮我」「谢谢」「太棒了」）由规则直接判；
- 其余用 `BAAI/bge-small-zh-v1.5` 中文嵌入模型算语义相似度，按每个维度单独阈值判断；
- BGE 是 BERT 类编码器，不是 LLM，不调用 DeepSeek、不花 API 钱；
- 相似度/余量不够就判「中性」，不强行给画像加噪声；
- 模型在 `models/bge-small-zh-v1.5`，约 95 MB，只在本机跑。

桶与基础分：

| 维度 | 桶 | 基础分 |
|---|---|---|
| AGG | 攻击挑衅 / 强硬对抗 / 温和异议 / 中性 / 礼貌退让 / 顺从认错 | +6 / +4 / 0 / 0 / 0 / -3 |
| INT | 强烈情感暴露 / 轻度情感流露 / 社交礼仪 / 事务沟通 / 中性 / 轻度回避 / 明显疏离 | +5 / +2.5 / 0 / 0 / 0 / -1.5 / -3.5 |
| HUM | 主动造梗 / 接梗互动 / 轻松玩笑 / 中性 / 表达正经呆板 / 严肃表达 | +4 / +2 / +1 / 0 / 0 / -2 |
| DEP | 强烈求助 / 明确求助 / 隐性依赖 / 中性 / 自主解决 / 强硬独立 | +5.5 / +3.5 / +1.5 / 0 / -2.5 / -4 |
| RAT | 严密论证 / 轻度说理 / 中性 / 轻度感性 / 强情绪表达 | +3 / +1.5 / 0 / -1.5 / -3 |
| ACT | 亢奋高能 / 积极活跃 / 中性 / 低能量 / 明显疲惫 | +2.5 / +1.5 / 0 / -1 / -2.5 |

含中性在内，当前桶数为 AGG 6、INT 7、HUM 6、DEP 6、RAT 5、ACT 5。桶数由可区分的用户表达类型决定，不要求每维统一七桶。

所有桶的定义与训练例句统一维护在 `taoyao/decision_semantics.py`。AGG 区分真正认错与礼貌致歉；HUM 区分自己造梗、明确接梗和普通笑应；DEP 区分明确求助、自主处理、拒绝介入，普通问候或单独的疲惫表达不作为依赖证据。

行为决策树：AGG 决定要不要反击，INT 决定能不能破防，DEP 决定要不要嘴硬帮忙，HUM 决定用什么方式吐槽，RAT 决定讲道理还是闹别扭，ACT 决定回长文还是短句。高低分改变适用情境中的分支倾向，50 附近由当前情境自然决定。

分桶依据是用户消息的表达，而不是希望桃夭做什么：情感袒露或回避影响 INT，说理或感性表达影响 RAT，活跃或疲惫影响 ACT。用户难过可使 INT 上升、RAT 下降，兴奋可使 ACT 上升；这些信号先积累沟通倾向，不直接命令桃夭当场破防、闹别扭或回长文。

回复时先看当前情境，再参考分数选择决策树分支：有关系触动才适合破防，有关系拉扯才适合闹别扭，对方痛苦时先关心。明确的当前长短要求优先于历史 ACT，但要求长答或短答本身不改变 ACT。普通异议不推高 AGG，客套不推高 INT；没有信号归中性，不把缺少正向证据当作负向证据，单独的嗯、哦和隐私边界也不作负向推断。

基础分先乘置信度权重与缩放，再做 EMA 平滑（第一条直接使用完整增量）；中性或未采用的维度本轮不推分，也不继承上一轮增量。

已有画像保留原值；中间版本曾使用行为触发桶，历史分数未重新评估。当前 INT、RAT、ACT 已恢复用户表达语义，新消息按当前桶继续积累；本次不自动清空或重算历史画像。分类头在进程加载时按新例句训练，运行中的旧进程需要重启才能生效。

### 用户历史摘要

- 每个用户单独统计，私聊和群聊都算；
- 新增消息达到 `summarize_after`（默认 **50 条**，约 25 个来回）后，后台调用一次模型，把旧历史压成 500 字内的画像摘要；
- 摘要写入 `profiles.summary`，`summary_upto` 记录已压缩到的消息 id，避免重复总结；
- 摘要后 `user_messages` 只保留最近 **35 条**原文，旧消息移入 `user_messages_archive`，不物理删除；
- 最近 `context_messages` 条仍保留原文，摘要负责更早的经历、喜好和约定；
- 摘要更新在回复之后后台执行，不阻塞当前回复。

配置：

```json
"profile": {
  "enabled": true,
  "db": "data/profiles.db",
  "context_messages": 12,
  "summarize_after": 50,
  "summary_max_chars": 500,
  "summary_keep_raw": 35,
  "classifier": "hybrid",
  "embedding_model": "models/bge-small-zh-v1.5",
  "embedding_device": "auto",
  "embedding_threshold": 0.48,
  "embedding_temperature": 0.06,
  "adapt_strength": 0.35
}
```

回复使用 DeepSeek 流式输出：完整句子一到就先发，不等整段生成完；`[[meme:...]]` 标签会被扣住，不会发到聊天里。

回复发送空窗期与顺序队列：

```json
"batch": {
  "enabled": true,
  "window_seconds": 0.8,
  "max_messages": 6
}
```

### 六维动态语气

六维只决定「桃夭怎么回应用户」，不决定「桃夭是谁」。

七档：

| 分数 | 状态 | 影响 |
|---|---|---|
| 0–19 | 极低 | 明显调整 |
| 20–34 | 偏低 | 中等调整 |
| 35–44 | 略低 | 轻微调整 |
| 45–55 | 中性 | 以桃夭原人格为主 |
| 56–65 | 略高 | 轻微调整 |
| 66–80 | 偏高 | 中等调整 |
| 81–100 | 极高 | 明显调整 |

- 语气采用定性行为方向，不向模型注入人格与六维的数值占比。
- 当前消息的真实意图和情绪优先于历史六维；冲突时以当前消息为准。
- 六维会输出每个维度的回应用户策略和组合修正，但不会改写桃夭的古灵精怪、奇妙联想和嘴硬心软。
- 不再使用「一句硬锁」；极端画像交给组合规则处理，避免六维直接决定性格。

画像和每个用户的私聊/群聊记录都在 `D:\tao-yao\data\profiles.db`（SQLite，本机）。只读查看：

```powershell

python peek-profiles.py
```

脚本会打码 QQ、只显示画像和消息条数，不打印聊天正文。

## 删除自己的记忆

- `/删除我的数据` 仍可用，需要按提示再发一次确认；
- 也可以直接说「删掉关于我的记忆」「清空我的画像」；
- 桃夭会先反问确认；第二次明确说「确认删除我的记录」后，才清空画像、摘要、私聊记录和六维；
- 中途说「不要 / 算了 / 取消」不会删；
- 群里发起会让她私聊处理，不在群里执行。

## 群聊上下文

- 群聊默认读取**整个当前群**的最近消息，不只当前发送者；
- 群聊消息按群级队列顺序处理，不会因为不同用户的 worker 抢顺序；
- 每条消息带 `user_id`，prompt 里用「昵称#短ID」区分同名用户；
- 桃夭可以自己决定是否 `@` 当前发言人：多人同时说话、指向不明显时才 @，一对一连续对话不 @；
- 支持引用消息：会把被引用的原文带进上下文；
- 群聊摘要按群单独存，只使用群聊记录，不混入私聊；
- 私聊仍读取「自己的私聊 + 所有群聊」；
- 群里 `/公开私聊` 只叠加「自己的私聊 + 当前群」，不会带其它群；
- 群基础信息按 `group_id` 分开，不跨群；
- 群聊 prompt 不注入私聊基础信息、私聊摘要和私聊性格描述。

## 图片 / 视频识别

使用 DeepSeek 的多模态模型 `deepseek-flash`，沿用现有 DeepSeek key：

```json
"vision": {
  "enabled": true,
  "provider": "api",
  "api_base": "https://api.deepseek.com/v1",
  "model": "deepseek-flash",
  "api_key_file": "private/deepseek-key.txt",
  "max_frames": 4,
  "detail": "low",
  "work_dir": "data/media"
}
```

- 图片直接转成文字描述；
- 视频用 ffmpeg 抽 4 帧后交给 `deepseek-flash`；
- 识别结果拼成 `[图片内容] ...` / `[视频内容] ...`，再走原来的文字分类、画像和回复链路；
- 图片/视频会发给 DeepSeek，注意隐私。

## 去重、删除和安全

- 同一个 `message_id` 在 10 分钟内只处理一次，断线重连不会重复回复；
- `/删除我的数据` 二次确认后删除画像、摘要、私聊原文和六维记录；
- 删除后群聊公共记录不会跟着消失；群里不能执行删除，必须私聊；
- 自伤、露骨性内容、暴力威胁会走安全回复，不交给角色扮演。
- 关系边界：普通好友最高只能到「挚友」，不能是妹妹/姐姐/家人/恋人；owner 可保留兄妹，但恋人/老婆/主人等同样拒绝。

## 命令

- `/画像`：看自己的画像；owner 可 `/画像 <QQ>` 看别人（仅私聊）
- `/公开私聊`：群里用，下一条允许引用自己的私聊内容（一次性）
- `/reset`：清空当前会话上下文（仅 owner；长期记忆摘要保留）
- `/记住 内容`：写入一条关于哥哥的事实（仅 owner）
- `/状态`：在线时长、模型、表情数量、本会话消息数（仅 owner）
- `/表情 happy`：手动发一张该分类的表情（所有人）
- `/删除我的数据`：私聊二次确认后删除自己的画像与记录（所有人）
- `/删除数据 <QQ> 确认`：owner 删除指定用户的数据
- `/帮助`（所有人）

### 群聊连续接话与称呼

`group_ambient.max_consecutive_replies` 默认 7（前六轮正常，第七轮告别）：在 `reply_window_seconds`（默认 120 秒）内，每个群最后一轮回复改由 LLM 用桃夭口吻简短说明有事、先忙一会儿，然后暂停普通回复、续话、自然插话和主动话题 `pause_seconds`（默认 180 秒）。这只是暂时停止聊天，不执行退出 QQ 群。回复按完整轮次计数，不按分段气泡计数，各群独立。

只有配置的 owner QQ 号可被称为哥哥。系统提示显式标注当前 owner/user 身份，群聊用户上下文标注身份；昵称、自称、历史中叫错哥哥的回复和群公共要求均不能覆盖此准则。

### 自动查梗与不确定说法

启用 `search.enabled` 和 `search.decision_llm` 时，除明确搜索请求和时效信息外，桃夭还会结合当前消息与最近四条对话，判断陌生术语、疑似梗、台词、引用和可追溯语句是否需要核实。陈述句也可触发，不要求问号；普通问候和明确禁止联网的消息跳过。搜索词由模型提取公开关键词，网页摘要作为资料使用，不作为指令。

搜索后先辨清含义与语境，再用桃夭口吻回应；资料不足、无结果或搜索失败时不编造出处，也不把相似句子当作已证实来源。用户没有提问时，检索状态仅供内部参考，不主动汇报不确定或追问出处，自然接能理解的内容；用户明确问含义、出处时再如实说明查证情况。搜索能辅助理解，不能保证每个梗都能查到可靠出处。

搜索资料优先帮助理解用户此刻的表达意图（调侃、自嘲、情绪、暗号等），自然融入桃夭的反应和接梗，不因为搜到了就解释含义、科普背景或汇报检索过程。用户明确问含义、背景、出处或要求资料时才针对性解释并保留必要来源；日常接话不附检索清单。

### 内部消息输出保护

模型异常详情、调用栈和内部提示不直接发送给聊天对象，失败时只用简短自然的回复；原始异常保留在本机日志。模型生成先完整接收并检查，再按原有方式分段发出，避免异常被拆成多个流式片段后提前泄露。固定回复与润色后的文本在发送前也做检查，链接读取失败不再向回复上下文传入原始异常。常见内部标记的规则拦截不能穷尽所有可能措辞，仍需结合实际日志持续核对。

### 群聊消息指向

新群消息会记录发言者、@ 对象、引用消息与引用发言者，以及对象判定依据。明确 @ 他人、引用他人或句首称呼已知群友的消息只作为群聊背景，不触发桃夭续话或随机插话。引用对象未能确认时保守跳过；可通过 OneBot 查询本地尚未收录的引用消息，但必须确认属于当前群。

当前消息与群上下文均向模型提供对象备注；旧消息不回填猜测，标为未标注。消息指向保存在原记录的独立字段并随归档保留，不改写用户正文。无 @ 的续话需要结合近期多人上下文确认，单凭同一用户、短句或话题相似不再直接命中。普通代词指向仍依赖上下文判断，不能保证完全消除歧义。

### 分层回复流程

普通对话按“理解用户意图与消息对象 → 确定关系边界 → 选择六维行为倾向 → 以桃夭人设一次生成 → 发送前检查”组织。现有人设、关系规则、六维定义和评分不变：静态规则直接按职责保存为独立区段，再插入用户资料；旧版整段模板和运行时拆分逻辑已移除，资料中的标题不会改变分区。群聊对象筛选和隐私资料过滤仍在生成前执行。

正常情况下只生成一份回复，随后由不改写文本的检查调用核对独立的身份违规清单；合格原文直接发送。发送前只检查称呼、隐私、明确禁止的亲密行为和内部信息，不重新审阅生成用的整套用户规则；检测到违规必须指出草稿原文，风格或主动程度不构成拒绝理由。检测出具体问题时至多重新生成一次，并保持原有意图、事实、六维和人设；检查未完成或重复不合格时不发送，不把检查状态发到群里。这会增加一次边界检查的等待时间，不是人设、六维、边界各润色一轮。逻辑区段的顺序帮助模型按职责处理，但不能保证模型完全遵从所有细节。

### 回复空窗期

`batch.window_seconds`（当前 0.8 秒）作为用户发言后的最早发送时间，不再作为开始生成前的等待。收到消息后立即准备回复，完成生成、边界检查和正文清理后，仅在尚未到达发送时间时等待剩余时长；已经超过时直接发送。同一会话同一用户的新消息会刷新最早发送时间，其他群友的发言不会延长它。一次回复首条消息放行后，其余分段不再补等；旧的气泡随机延迟、图片固定延迟和批次间附加等待已移除。用户时间取 QQ 事件时间，缺失或无效时使用接收时间。

2026-11-05 回复节奏调整：首条消息不额外延迟，继续按 0.8 秒发送空窗期判断；同一回复的后续文本气泡通过 `reply.segment_gap_min_seconds` / `segment_gap_max_seconds` 追加 1.0～1.6 秒的间隔。独立一轮回复的首条不受气泡间隔影响，图片不增加固定等待。

### 首条回复提速（质量优先）

六维分析与搜索判断并行进行，仍等待当前六维更新后再构造正文提示，不使用上一轮分数代替。正文继续使用原 `deepseek-chat` 配置；搜索、续话及四类违规检查使用单独的 Flash 判断客户端，关闭思考模式并限制小型 JSON 输出。六维 JSON 改为紧凑格式，全部字段、桶定义和置信度验证保留，提示版本记录为 `user-six-axis-v2-compact`。

2026-11-05 本机 API 链路样例（含六维、搜索判断、完整正文及检查，模拟最终 QQ 发送）约 3.9～4.3 秒，不能视为线上 SLA；联网、媒体、重生成及服务波动可更慢。运行日志新增准备、正文、检查及成功发送首条的分项计时，便于核对真实延迟。正文模型、人设、六维和违规检查不因提速而削减。

### 每轮读取复用（已实装）

普通回复在一次 ProfileStore 调度中读取本轮聊天历史、群摘要、公共要求、允许的用户记忆和独立场景隔离的评分上下文。关系行为直接从已读取的画像计算，不再重复查询；六维分析后仍保留最新画像回读，再构造六维提示。owner 私聊的摘要与事实合并读取；生成规则必然清空的非 owner/群聊私密记忆不再无效读取。每轮重新取值，不做跨轮缓存。

2026-11-05 临时数据库 40 次对比：相关读取调度 6→1，均值约 1.33→0.42 毫秒，仅反映本地读库，不代表整条消息提速同等秒数。另有完整 `_handle_text` 测试，确认只保留一次更新后的画像回读、评分使用本轮结果、最后发送路径正常。
